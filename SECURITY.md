# Security policy

## Supported versions

| Version | Security fixes |
| --- | --- |
| v0.5.x | Current supported release line after publication |
| Earlier versions | No planned security backports |

Do **not** file a public issue containing exploit details, secrets or private project files. After the repository is created, the owner should enable [GitHub Private Vulnerability Reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository) before publishing. Use the repository's **Security → Report a vulnerability** action to send a private report. If that action is unavailable, open a public issue asking the maintainers to provide a private reporting channel, without disclosing the vulnerability itself.

Please include affected version, reproducible steps and impact. Do not attach copyrighted manga pages, personal projects or unsanitized logs. The maintainer will acknowledge and triage the report privately; no response-time SLA is promised for this initial release.
